## CRC-16 algorithm (FIT protocol, not part of `profile.js`)

The FIT binary trailer/header CRC is documented in the FIT protocol spec (not in this JS
profile file) as a nibble-lookup CRC-16 with the following well-known table and update
routine (reproduced from the publicly documented FIT SDK reference implementation, e.g.
`fit_crc.c` / `CRC.java` shipped with the Garmin FIT SDK; re-implemented from that public
algorithm description, not copy-pasted from a specific file we fetched):

```
crc_table[16] = {
  0x0000, 0xCC01, 0xD801, 0x1400, 0xF001, 0x3C00, 0x2800, 0xE401,
  0xA001, 0x6C00, 0x7800, 0xB401, 0x5000, 0x9C01, 0x8801, 0x4400
}

update(crc, byte):
  tmp = crc_table[crc & 0xF]
  crc = (crc >> 4) & 0x0FFF
  crc = crc ^ tmp ^ crc_table[byte & 0xF]

  tmp = crc_table[crc & 0xF]
  crc = (crc >> 4) & 0x0FFF
  crc = crc ^ tmp ^ crc_table[(byte >> 4) & 0xF]

  return crc
```

Implemented independently in both `spike/fit-encoder.js` (JS, for encoding) and
`spike/verify_fit.py` (Python, for decoding/verification) so the two are a cross-check of
each other, not a single shared implementation.
